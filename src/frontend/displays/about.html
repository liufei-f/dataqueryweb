How it works

DataQuery reads papers the way a curator would: it works out whether a paper produced new QTL data, and where those results can be downloaded. Save eligible papers, build their data manifests, and review the evidence before exporting approved rows.

  1. FindEurope PMC search, or one DOI / URL
  2. Readfull text, preprint API, publisher page
  3. Extractlinks, accessions, sentences — no AI
  4. JudgeLLM: new data? which link?
  5. Savekeep eligible papers and source links
  6. Builddownload, process and validate data
  7. Reviewapprove manifest rows for export

1. Find papers

Search literature queries the Europe PMC REST API, which also indexes bioRxiv and medRxiv. Plain keywords are matched against titles and abstracts; Europe PMC syntax (e.g. AUTH:"Smith J" AND eQTL) is passed through unchanged.

OptionWhat it does
YearsPublication-year range (PUB_YEAR); either end may be empty. This year / 2 yrs / 5 yrs / Any fill it in.
SortRelevance, or Newest first — with a year range, the quickest way to reach newly published data.
SourcesAll, journals only, or bioRxiv + medRxiv preprints only.
Only papers mentioning QTLAdds eQTL / sQTL / pQTL / caQTL / mQTL / "quantitative trait loci" to the query.

DOI or URL inspects a single paper: a DOI, a doi.org / publisher / PMC / PubMed / bioRxiv / medRxiv link, a PMID or a PMCID. A link straight to a data repository (Zenodo, figshare…) is listed with its files.

Results appear as each paper finishes. Stop ends a search at any time: papers already read stay on the page, and the server cancels the rest, so they stop using LLM tokens and nothing more is auto-saved. The options are kept in the page URL, so a refresh or a shared link repeats the same search.

2. Read each paper

Every route that is reachable is used; the Read: line under each paper lists which ones were.

RouteWhat is read
PMC full textEurope PMC fullTextXML, or NCBI PMC when Europe PMC has none; for preprints, Europe PMC's preprint full text when it exists.
bioRxiv / medRxiv APIPreprint metadata from api.biorxiv.org and, once published, the journal DOI. The journal version is then read too, and its data sources are merged in, prefixed with the journal name.
Accession annotationsEurope PMC's text-mined accession numbers (GEO, EGA, dbGaP, ArrayExpress…), available even for some closed papers.
Publisher pageThe article page via doi.org when there is no open full text. Many publishers — and bioRxiv/medRxiv — refuse automated requests; the paper then says so.
Repository APIsZenodo and figshare records are expanded into direct file links with sizes.

If Europe PMC itself is down, a single-paper lookup carries on with the other routes; a keyword search says so and asks you to retry.

3. Extract and rank links (rules, no AI)

From the text, every data link, dataset DOI and accession is collected with the sentence it came from — including links in Data availability statements and supplementary files whose caption mentions QTL results. Each is ranked:

  • high the sentence is about QTL results / summary statistics, and it is in a data availability statement or says the authors share it;
  • medium part of that evidence — e.g. an availability statement about raw data, or an accession found by Europe PMC's text mining;
  • low incidental: software, reference files, resources the paper merely downloaded (hidden by default).

Access is marked open, controlled (EGA, dbGaP — needs an application), request or unknown.

4. AI check

Rules cannot tell a paper that mapped QTLs from one that only used published QTLs (Mendelian randomization, SMR, colocalization, TWAS…). With AI check on, an LLM reads the title, abstract, data availability statements, the numbered list of found links and — when it was read — the full text, and answers:

  • three factual questions — did the authors map QTLs, do they only reuse published QTLs, do they say where their results are — each answered yes / no / unclear with a verbatim quote, plus QTL types, species, tissues or cells and a one-sentence reason;
  • which found links hold the paper's own results — marked AI: QTL summary statistics, results browser, supplementary table or raw data — and whether download is open, controlled, on request or not found.

The model does not choose the verdict or the confidence: the program derives both from its answers with the fixed scoring rubric below, so the same answers always give the same result.

Full text first. The full text is sent with data, QTL and accession paragraphs first, up to the configured length, so the verdict rests on the methods and the data statement rather than the abstract. The model answers with link numbers, never URLs of its own, so it cannot invent a download address.

Web search when the text is not enough. If the full text could not be read, or the model says "new data" but no found link holds it, a model with web access searches for the article itself, opens it and the repository pages, and reports the data URLs with the sentence and page they came from. Each such URL is then requested once: URLs that do not exist are dropped, and ones that exist but refuse automated access are marked link blocked. Expand AI web search under a verdict to see what it searched and opened.

Fallback. If the main model is out of quota or fails, a keyless model takes over for the rest of the search; its verdicts are marked (fallback). The AI can be wrong — the reason and the quoted sentences are always shown so you can check.

5. Auto-save and review

With Auto-save when the AI is sure on, a paper goes into Saved records by itself — marked 🤖 Auto-saved — only when all of these hold:

  • the verdict is “New QTL data” with confidence ≥ {{ (autosave.min_confidence * 100) | round | int }}% by the rubric;
  • the verdict came from the main model{% if autosave.allow_fallback %} or the fallback{% else %}, not the fallback{% endif %};
  • the AI named a location holding QTL results: summary statistics, a results browser or a supplementary table.

Only those locations are saved; raw data and code links are not. An automatic save never overwrites a record you saved, nor your note. Every other paper stays on the page with the reason, e.g. Needs human check: confidence 85% < 90%.

The filter above the results sorts papers into Needs human check, Auto-saved, Saved by you and No new QTL data, with counts. Spot-check auto-saved rows and press Confirm (the record becomes yours) or Remove. Any other row can be saved with Save.

Saved papers are not re-read. A paper already in Saved records — matched by DOI (or a preprint's published DOI), PMID, title or article URL — is not sent to the AI again, to save tokens. It shows AI check skipped, with a Re-check with AI button for when you want a fresh verdict.

6. Saved records

Saved records is one row per publication and download location. Saving the same pair again updates it (http/https, www. and a trailing slash don't make it a different location). You can filter, add a curator note, confirm auto-saved rows, delete, and download the table as TSV or CSV — with the column names of LocusView's qtl-data-agent review table, plus saved_by, ai_confidence and a few more. Records are kept in {{ db_path }}, so they survive restarts. On the search page, papers and rows already saved are marked, with the date.

7. Build data and manifest rows

Open Manifest rows and use Process data for one paper, or filter the table and choose Build all shown. Building uses the configured LLM to investigate the paper, follow repository links, read README files and inspect data headers. A QTL-like software name alone does not establish a new QTL data type or dataset.

With downloads enabled, processing downloads source files into the paper’s data folder, prepares importer-compatible tables where needed, and validates their fields. Archives can be read directly; a separate extracted folder is not required. Build completion alone does not mean the data is usable: check Data result / success and the evidence in Details.

The download budget defaults to 1,000 GB per paper and is also constrained by free disk space. Downloading, scanning large archives, conversion and validation can take substantial time. Closing your browser does not stop a server-side build. Use Stop to cancel; the interrupted paper may need to be rebuilt.

Journal metadata is filled when processing can resolve it. Sample size means the number of genotyped donors used for that context’s QTL analysis, rather than the number of cells or the overall cohort size. Missing values remain Unknown; different contexts are listed separately.

8. Understand file counts and results

LabelMeaning
DownloadedUnique registered source files still present on the server. Generated outputs and unregistered manual uploads are excluded. An archive counts as one downloaded file.
No need to processManifest entries whose downloaded data can be used without conversion.
Need to processManifest entries still requiring conversion, including failed processing attempts.
ProcessedManifest entries whose conversion has completed.
Manifest rowsPlanned data entries generated by processing. One entry can reference multiple files; this is not a file count.
Queued / ProcessingProcessing has not started or is still running; a final result is not yet available.

Needs you should explain the bottleneck, your next action and the relevant application or download URL. Registration, an access application or a browser-only download may require your help. A network error, unsupported data type or processing failure has its own status and does not by itself mean you must request access.

When the paper’s conversation panel is available at the top of Details, paste access instructions, README text, relevant URLs or server paths for files you supplied. Send the information to the AI, then choose Continue processing with this context to start processing using that conversation. Sending a message alone does not download or process data. AI replies are suggestions; processing still needs to verify the sources and files.

9. Review and export

Human decision classifies the entire paper as QTL data, Not QTL data, or Needs recheck. Marking a paper Not QTL data excludes it from subsequent processing.

Review checks individual manifest entries. Select Review rows to open the first pending entry. Under Correct and decide, inspect the source evidence, preview and column mappings, then edit the fields that will be exported.

  • Save changes saves edits without approving the entry.
  • Approve includes the entry in the approved manifest export, subject to validation checks.
  • Reject excludes the entry from that export.
  • Reviewer note stores your review comment separately from the manifest data fields.

Download approved exports approved entries to the manifest TSV. Download all with evidence exports candidate entries and their review evidence. Column filters combine, so you can narrow the list by journal, context, sample size, build state or result.
